# ADR-001: Store permanent link records on Nostr relays

## Status

Accepted

## Date

2026-07-31

## Context

The product needs normal browser short links without a database the operator hosts or manages. Link data must survive replacement of the redirect service. Links are immutable, so a mutable database is unnecessary.

## Decision

Publish signed, immutable link records to multiple Nostr relays. The redirect domain runs a stateless resolver that reads and verifies those records on demand.

## Alternatives considered

### Hosted key-value store

Operationally simple but violates the no hosted database constraint and makes one provider the data owner.

### DNS records

Durable and simple, but record creation and changes require zone control, propagation is slow, and each link consumes DNS control-plane state.

### IPFS/IPNS

Content addressing suits immutable content, but mutable discovery and reliable browser redirects still require a gateway/pointer design. It adds complexity without improving this v1's core workflow.

### On-chain registry

Strong durability but poor fit for frequent low-value link creation because of fees, latency, and operational friction.

## Consequences

- Relay retention and availability are external dependencies, mitigated by replication.
- The redirect domain remains an availability dependency, though not the sole data store.
- Nostr event signing supplies integrity and provenance without accounts. The protocol uses regular kind `8003`, not NIP-01's replaceable-event range, so relays are expected to retain permanent records.
- The first implementation must select relay endpoints and test relay failure behavior before launch.
