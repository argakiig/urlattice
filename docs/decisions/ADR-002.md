# ADR-002: Use Cloudflare Workers and a fixed public relay set

## Status

Accepted

## Date

2026-07-31

## Context

The redirector needs an ordinary browser domain, an edge request handler with outbound WebSocket support, and three independent relay endpoints. It must not require a database, KV namespace, durable object, or private key.

## Decision

Deploy the stateless redirector to Cloudflare Workers at `urlattice.xyz`. Its initial relay configuration is:

- `wss://nos.lol`
- `wss://relay.primal.net`
- `wss://relay.nostr.com`

On 2026-07-31, all three completed a `#c` query and accepted a signed, ephemeral kind-8003 probe. Cloudflare Workers documents outbound WebSocket support: <https://developers.cloudflare.com/workers/runtime-apis/websockets/>.

## Consequences

- DNS and deployment access to the `urlattice.xyz` Cloudflare zone are required only for deployment, not development.
- Relay endpoints are runtime configuration and may be changed by a reviewed configuration release; they are not link storage.
- The resolver must impose per-relay timeouts and a connection budget because each request opens outbound connections.
- A deployed Worker must not bind Workers KV, D1, Durable Objects, R2, or another persistence product.
